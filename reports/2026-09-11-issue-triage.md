## #103 — Support for S/4HANA on-premise via SAProuter · `connectivity` · question-meta · effort small

Re-triaged by hand (the workflow agent hit the schema retry cap). **Verdict: answerable question, no native support, closeable once answered.**

- **Finding:** vsp speaks ADT over **HTTPS** and honours standard `HTTP_PROXY`/`HTTPS_PROXY` (`pkg/adt/config.go:307`, `http.ProxyFromEnvironment`). **SAProuter is not an HTTP proxy** — it is SAP's TCP-tunnelling router (route strings `/H/host/S/port`, port 3299), a GUI/RFC-era mechanism. There is no `/H/.../S/...` route-string parsing anywhere in `pkg/adt` (grep clean).
- **Proposal (answer on-issue):** to reach an on-prem ADT endpoint across the boundary, one of: (a) reach the ADT HTTPS port directly; (b) put a real HTTP forward proxy in front and set `HTTP(S)_PROXY` — vsp already routes through it; or (c) have Basis configure a SAProuter **native/TCP tunnel** of the HTTPS port (a `P` route-permission entry) and point `SAP_URL` at the tunnelled `host:port`. `SAP_URL` is always a plain `https://host:port` — never a SAProuter route string. Native SAProuter route-string support would only make sense on the **RFC** path (`open-rfc-go`), and would be a separate feature request if wanted. Close as an answered question.
